提案: `zodFail` を「1行ずつ分解 → 型を後付け → 実戦で1回使う」の順で覚える  
理由: いきなり完成形を見ると難しいので、実行される処理の順番で理解した方が定着するため  
代替案: 丸暗記する方法もあるが、少し形が変わると使えなくなるため非推奨  
最小実装: まずは `error: any` 版で動きを理解し、その後に型を厳密化する

---

まず、あなたが覚えたいコードです。

```ts
const zodFail = (
  res: Response,
  error: { errors: { path: (string | number)[]; message: string }[] }
) =>
  res.status(400).json({
    status: 'fail',
    errors: error.errors.map((e) => ({ path: e.path, message: e.message })),
  });
```

## これが「何をしているか」だけ先に

**やってることは2つだけ**です。

1. HTTP 400 を返す  
2. Zodエラーを見やすい配列に変換して JSON で返す

---

## 1行ずつ分解

### 1) 引数 `res`
- `Response` は Express のレスポンスオブジェクト
- `res.status(...).json(...)` するために必要

### 2) 引数 `error`
- Zod が失敗時に持っているエラー情報
- その中の `errors` 配列だけ使っている

`errors` の各要素はだいたいこういう形:
```ts
{
  path: ['title'],   // どの項目でエラーか
  message: 'タイトルは必須です'
}
```

### 3) `res.status(400).json(...)`
- 400 = 入力不正
- JSONで返す本体を作っている

### 4) `error.errors.map(...)`
- `errors` 配列を1件ずつ変換
- 必要な情報だけ `{ path, message }` にして返す

---

## 型注釈が長く見える部分の正体

ここ:
```ts
error: { errors: { path: (string | number)[]; message: string }[] }
```

意味は日本語でこれだけです:

- `error` には `errors` という配列がある
- 配列の1件は `path` と `message` を持つ
- `path` は文字や数字の配列

**つまり「エラーの中身の形を説明しているだけ」**です。

---

## 学習用に2段階で覚える（重要）

### 段階A（まず動きを理解）
```ts
const zodFail = (res: Response, error: any) =>
  res.status(400).json({
    status: 'fail',
    errors: error.errors.map((e: any) => ({ path: e.path, message: e.message })),
  });
```

### 段階B（次に型を厳密化）
```ts
type ZodIssueLike = { path: (string | number)[]; message: string };
type ZodErrorLike = { errors: ZodIssueLike[] };

const zodFail = (res: Response, error: ZodErrorLike) =>
  res.status(400).json({
    status: 'fail',
    errors: error.errors.map((e) => ({ path: e.path, message: e.message })),
  });
```

完成形より、こっちの方が理解しやすいです。  
（意味は同じ）

## 実戦での使い方（Controller）

```ts
const parsed = createTodoSchema.safeParse(req.body);
if (!parsed.success) {
  return zodFail(res, parsed.error);
}
```

- `safeParse` が失敗したら `parsed.error` をそのまま `zodFail` に渡す
- これだけで 400 のエラー形式が統一される

---

提案: 明日からは「段階Aの `any` 版」で一度通し、そのあと段階Bに上げる  
理由: 止まらず進みながら理解できるため  
代替案: いきなり完成形を維持する方法もあるが、負荷が高い  
最小実装: `zodFail` を1つ作り、`create` だけで先に使う（全メソッド一気にやらない）
